# STVR

STVR 是一个面向代码测试质量管理的智能评估与修复系统。系统围绕 Python 函数和小型项目，形成“可信测试、执行验证、质量证据、缺陷诊断、修复推荐”五步闭环，帮助开发者获得可执行、可解释、可复核的测试结果。

## 系统定位

大模型可以快速生成测试代码，但生成结果经常存在弱断言、边界覆盖不足、异常路径缺失、不可执行或假通过等问题。STVR 的目标不是简单输出一段测试代码，而是构建一个质量闭环：

`代码输入 -> 可信测试 -> 执行验证 -> 质量证据 -> 缺陷诊断 -> 修复推荐 -> 报告沉淀`

系统面向软件开发、教学测评、开源维护和企业代码质检等场景，强调测试结果的可用性、可信性和可追踪性。

## 核心功能

- 用户登录、注册、退出和基础账号管理。
- 支持粘贴单个 Python 函数，也支持上传 Python 文件或小型项目压缩包。
- 自动识别目标函数，生成 pytest 或 unittest 风格测试候选。
- 支持自动引擎、真实大模型和沙箱生成三种策略。
- 在轻量隔离环境中执行测试，记录执行状态、覆盖率、失败日志和异常信息。
- 使用轻量变异测试评估测试用例对潜在缺陷的捕获能力。
- 对候选测试进行质量评分、推荐排序和失败原因归类。
- 生成修复后的测试建议，并支持测试文件下载。
- 支持批量函数评估、历史记录查看、评估详情页和报告导出。
- 管理员可查看模型配置、模型对比、数据资产和质量审计页面。

## 五步可信闭环

1. 可信测试：解析代码语义，结合模型生成和规则候选构造多组测试样例。
2. 执行验证：在受限执行环境中运行候选测试，检查语法、导入、pytest/unittest 和运行异常。
3. 质量证据：综合通过率、覆盖率、变异分数、断言密度、失败日志和边界覆盖形成质量分。
4. 缺陷诊断：识别弱断言、边界缺失、契约错误、异常路径不足和运行失败等问题。
5. 修复推荐：根据诊断结果生成改进测试，并沉淀报告、测试文件和推荐理由。

## 创新点

- 从“生成测试”升级为“测试质量管理”：系统不会直接相信模型输出，而是先执行、再评估、再推荐。
- 构建五步可信闭环：可信测试、执行验证、质量证据、缺陷诊断和修复推荐形成完整链路。
- 引入多维质量信号：覆盖率、变异分数、断言密度、边界覆盖和失败日志共同决定推荐结果。
- 支持失败感知修复：系统能解释测试为什么弱，并给出可运行的改进版本。
- 支持项目级批量评估：从单函数演示扩展到小型项目的函数扫描和批量报告。
- 区分用户视图和管理视图：普通用户关注当前代码检测，管理员查看数据、模型和审计证据。

## 可信性说明

STVR 的可信性来自可验证证据，而不是单一模型结论：

- 可执行性由真实测试运行结果验证。
- 测试充分性由覆盖率和变异测试衡量。
- 失败原因由执行日志和规则审计共同归类。
- 推荐结果由质量分排序，不直接等同于模型输出。
- 历史记录、测试代码和报告可追踪，便于复核。
- 管理视图保留模型对比和数据资产，用于说明系统设计依据。

## 运行方式

进入 UI 服务目录后启动：

```bash
cd stvr/ui
python server.py --port 7860
```

浏览器访问：

```text
http://127.0.0.1:7860/
```

默认账号：

```text
demo / demo123
tester / test123
admin / admin123
```

本地大模型可通过环境变量配置。未配置或不可运行时，系统会自动使用沙箱生成策略，保证基础演示流程可用。

```bash
export STVR_PROVIDER=local
export STVR_LOCAL_ENABLED=1
export STVR_LOCAL_MODEL=/path/to/qwen2.5-7b-instruct
python server.py --port 7860
```

## 使用流程

标准使用流程：

1. 使用 `demo / demo123` 登录系统。
2. 在控制台粘贴一个 Python 函数，或点击载入示例。
3. 选择测试框架和生成引擎，点击开始评估。
4. 查看可信测试、执行验证结果、质量证据和缺陷诊断。
5. 查看修复推荐并下载测试文件。
6. 进入批量评估页，导入 .py 文件、项目文件夹或项目 ZIP，扫描并批量评估多个函数。
7. 进入报告页，展示当前评估图表、热力图和报告文本。
8. 使用管理员账号查看模型配置、模型对比、数据资产和质量审计证据。

## 运行边界

系统面向 Python 函数和依赖规模可控的小型项目评估。为了保证运行稳定，系统默认采用轻量隔离执行环境，并对文件大小、导入模块、执行时间、内存、日志和项目规模进行限制。复杂依赖项目需要专用依赖环境与更高等级隔离，多语言任务需要独立的解析、执行和评价链路。

## 项目结构

- `ui/`：系统界面和本地服务入口。
- `scripts/`：数据构建、生成、评估、训练和分析脚本。
- `configs/`：标注规则和外部项目配置。
- `src/`：共享工具代码。
- `readme.md`：系统说明、运行方式和使用流程。
